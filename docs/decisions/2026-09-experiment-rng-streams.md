# 実験の乱数を「木用」と「手法用」に分ける

**ステータス: Implemented**（2026-09-14）

`SEED` を固定しても、レイアウト実装を変えると生成される木の集合がずれていた。
`experiments/lib/runner.js` で木用と手法用に独立した乱数ストリームを張って解消した。

## 何が起きていたか

試行ループは木の生成と手法の実行が同じ `Math.random` を共有していた。

```js
for (let trial = 0; trial < trials; trial++) {
  const data = generateScaleFreeTree(...);   // ← 乱数を消費
  for (const [methodName, fn] of Object.entries(methods)) {
    measure({ fn, ... });                    // ← SA も乱数を消費
  }
}
```

SA は焼きなましの過程で `Math.random` を引く。レイアウトが変わると引く本数が変わるため、
**それ以降の試行の木までずれる**。結果として、

- `methods/existing.js` を1行も触っていないのに、既存手法の平均が動く（実測で最大0.0014）
- 手法セット（`METHOD_SET`）を変えただけでも木が変わる
- 「実装を変える前後で同じ木を使って比較する」ができない

`SEED` は「同じコードの同じ実行」の再現は保証していたので、単独の実行結果は再現できる。
壊れていたのは**コード変更をまたいだ比較**のほう。

## 対処

`seed` と `seed ^ 0x9e3779b9` から2本のストリームを作り、木を生成する間だけ木用に
差し替える（`makeTree`）。木は `SEED` と生成順だけで決まるようになる。

`SEED` 未指定のときは従来どおり素の `Math.random` を使う（過去の挙動を変えない）。

## 検証

`SEED=1 TRIALS=3 NUM_NODES=60` で `METHOD_SET` を `paper5` / `growth5` と変えて実行し、
既存手法の値が両方で一致することを確認した（low/1:4 = 0.0981、low/1:2 = 0.1573）。
修正前はここがずれていた。

## 影響

過去の結果JSONとは木の集合が違うので、**数値を直接比較しない**こと。
`experiments/results/` は追跡していないため、比較したい場合は同じコードで回し直す。
