# 美的基準5を満たすよう、著者の修正と均等配置を入れる

## 背景

論文付録C の `separate` は `dist > 0` のときだけ部分木を動かす。部分木は自分の原点から出発するので、根が広い子の
中央に乗っていて最初から左兄弟より右にあると、押されずに隙間が残る。置く順を逆にすると隙間はできないので、
反転した木の絵が鏡像にならない。

[2026-10-linear-vanderploeg.md](2026-10-linear-vanderploeg.md) ではこれを論文どおりの挙動として残したが、著者は公開後に
バグとして修正していた（[issue #2](https://github.com/cwi-swat/non-layered-tidy-trees/issues/2)、リポジトリの README と
`Paper.java`）。当時は付録C だけを正として、著者のコードを確かめていなかった。

## 判断

1. **最初の輪郭の組（兄弟の根どうし）は必ず動かす。** `dist` が負なら左へ動く。部分木の移動量は全ての組の `dist` の
   最大値になる。著者の条件 `first && dist < 0 || dist > 0` は、最初の組の `dist` がちょうど 0 のとき印が次の組へ
   持ち越され、誤って左へ動く。整数の寸法の木400本中5本で重なりが出たので、最初の組を無条件に扱う形にした。
2. **均等配置（`spacing`）を既定で有効にする。** 修正だけでは鏡像にならない木が残る。

`vanderPloegLayout` と `methods/growthIncremental.js` の両方に入れた。差分更新版は押した各回を `steps` に残し、
均等配置を輪郭に反映せず子の位置と外枠にだけ反映する（van der Ploeg が `secondWalk` で行うのと同じ）。

## 鏡像の検証

反転した木を配置して鏡に映し、元の図と全ノードの位置を比べた（8〜19ノードのランダムな木3000本、シード11）。

`test/vanderploeg.test.mjs` に鏡像のテストを置いた。

## レイアウト全体への影響

出力はほとんど変わらない。面積効率は `|V|=300`、シード1、600試行×6手法で、existing の1試行（+0.649%）だけが変わった。
修正のあり／なしを n=100, 300, 1000 の5840回で比べると、面積が上がったのが3回、下がったのは0回だった。
いずれも開発環境での予備測定で、論文用の結果ではない。

golden は `ui-budget-lpt` / `ffd` / `bfd` の `medium_extreme.json`、2:1 の3ケースだけ更新した（エッジが1本減り、ノードの
表示面積は lpt で -0.57%、ffd・bfd で -0.009%）。配置の悪化ではなく、二分探索の止まる位置が変わった結果である。
H=26968 でアスペクト比が 2.202 から 2.0014 になって許容誤差5%に入り、31066 まで探索せずに止まる。目標の 2 には
1.968 だった以前より近い。

## 均等配置がほとんど発動しない理由

畳んだ木の配置を数えると、左の離れた兄弟の輪郭まで届いた分離が n=300 で 23,539 回あり、押されて発動したのは6回だった
（n=3000 では 16,888 回中 334 回）。畳む前の木では 11,071 回中 162 回で、畳むと発動しにくい。

新しい部分木は隣の兄弟の根より右に置かれる。ダミーは子を持たない長方形で、右端が隣の兄弟より左にあるので押せない
（届いた組の約30%がダミーで、発動は0回）。ダミー以外でも、離れた兄弟の子孫が右へ、新しい部分木の子孫が左へ広がって、
間の兄弟より下で出会う必要がある。最終の配置で発動した7回（864回中）は、どれもノード面積が変わらなかった。

## 残っていること

二分探索が「許容誤差に入ったら止まる」ので、配置の小さな変化で止まる H が変わる。最良の H を選ぶ形にするかは
全手法の実験値に関わるため、別の作業として調べる。
